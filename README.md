# Nasos: Arduino Nano + ESP32

## Архитектура

1. **`v1.ino` (Arduino Nano)**
   - читает аналоговые/дискретные входы;
   - управляет реле и VFD;
   - обменивается телеметрией и командами с ESP32.

2. **`esp32_controller.ino` (ESP32)**
   - логика двух насосов и защиты;
   - веб-интерфейс и API;
   - уставки в RAM (через меню настроек).

3. **`data/index.html`**
   - панель мониторинга;
   - раздел «Настройки» со всеми параметрами из кода;
   - кнопки сброса аварий и принудительного включения по каждому насосу.
2. **`esp32_controller.ino` (ESP32)** — вся логика:
   - алгоритмы скважинного и домашнего насосов;
   - защиты по перегрузке и сухому ходу;
   - расчёт статистики (время работы, объём);
   - веб-сервер (LittleFS + REST API).

## Подключение Nano ↔ ESP32 (I2C)

- `Nano A4 (SDA)` ↔ `ESP32 GPIO21 (SDA)`.
- `Nano A5 (SCL)` ↔ `ESP32 GPIO22 (SCL)`.
- `GND Nano` ↔ `GND ESP32`.

Подключение I2C для этой связки должно быть **строго** таким, без переназначения пинов.

> ⚠️ **Важно по уровням:** у Nano I2C линия подтягивается к 5V, а ESP32 не 5V-tolerant. Используйте двунаправленный I2C level shifter (BSS138) либо подтяжку обеих линий к 3.3V на стороне ESP32.

### Пошаговый чек-лист по устранению проблем связи I2C

1. Установите **двунаправленный I2C level shifter** (например, модуль на BSS138) между линиями `SDA/SCL` Arduino Nano и ESP32.
2. Проверьте подтягивающие резисторы:
   - сторона Nano (HV) должна быть подтянута к **5V**;
   - сторона ESP32 (LV) должна быть подтянута к **3.3V**.
3. Убедитесь, что земля общая: `GND Nano` и `GND ESP32` обязательно соединены.
4. После монтажа повторно проверьте обмен по I2C:
   - перезапустите ESP32;
   - откройте Serial Monitor;
   - убедитесь, что телеметрия от Nano приходит, а сообщения `Nano link timeout` отсутствуют.

## Прошивка Arduino Nano для работы с ESP32

- Для связки с `esp32_controller.ino` прошивайте **только** `v1.ino`.
- `Osnova.ino` для этой связки не подходит: в нём отсутствует обмен по протоколу `TEL,...*CRC` / `CMD,...*CRC`.
- В `v1.ino` обязательно должны присутствовать инициализация и обработчики I2C-slave:
  - `Wire.begin(NANO_I2C_ADDRESS);`
  - `Wire.onReceive(onI2cReceive);`
  - `Wire.onRequest(onI2cRequest);`
- При старте `v1.ino` печатает warning-баннер с активной распиновкой уровней: `L1=D4, L2=D5, L3=A6, L4=A7`.
- В рантайме добавлена sanity-проверка: при нестабильном I2C и "залипших" `L1/L2` выводится явное предупреждение о неверной проводке (проверить, что `L1/L2` не сидят на `A4/A5`).

### Проверка после прошивки Nano

1. Перезапустите ESP32 после загрузки `v1.ino` в Nano.
2. Откройте Serial Monitor ESP32.
3. Убедитесь, что в логах больше не появляется строка `Nano link timeout`.
4. Если таймауты остаются:
   - проверьте проводку SDA/SCL/GND;
   - проверьте I2C level shifting (5V↔3.3V);
   - убедитесь, что в Nano действительно загружен `v1.ino`, а не `Osnova.ino`.

## Назначение входов уровней в `v1.ino`

- `L1` → `D4` (цифровой вход).
- `L2` → `D5` (цифровой вход).
- `L3` → `A6` (аналоговый вход, пороговая обработка).
- `L4` → `A7` (аналоговый вход, пороговая обработка).

`A4/A5` зарезервированы только под I2C и не используются как уровневые датчики.

**Legacy wiring note:** legacy wiring of level sensors to `A4/A5` is incompatible with I2C mode.

### Важно для монтажа

- Не подключайте датчики уровней к `A4/A5`, если Nano работает с ESP32 по I2C.
- Если в старом монтаже `L1/L2` были заведены на `A4/A5`, обязательно перенесите провода на `D4/D5`.

## API ESP32

- `GET /` — веб-интерфейс
- `GET /state` — текущее состояние
- `GET /settings` — текущие настройки
- `POST /set?param=...&value=...` — изменить параметр
- `POST /action?pump=well|house&cmd=...` — команды (`reset_alarm`, `force_on`, `force_off`)
- `GET /logs_well`, `GET /logs_house`
- `POST /clear_logs_well`, `POST /clear_logs_house`
- Главная страница: `/`
- Текущее состояние (JSON): `/state`
- Логи: `/logs_well`, `/logs_house`
- Настройки: `POST /set?param=SETPOINT_BAR&value=...`
- Экспорт CSV: `/export_well`, `/export_house`

## Wi‑Fi

ESP32 работает в режиме **AP + STA**:
- AP: подключение напрямую к плате (по умолчанию `Nasos-ESP32` / `12345678`)
- STA: подключение к роутеру (`wifi_ssid` / `wifi_pass` в настройках)
- `WebServer` (встроенная в ESP32 core)
- `LittleFS`
- `ArduinoJson`

## Важное по принудительному режиму

- Для скважинного насоса принудительный режим обходит уровни бака.
- При этом защиты по току и таймерам остаются в приоритете.
- Аналогично для домашнего насоса: аварийные защиты всегда имеют приоритет.
- Добавить сохранение уставок в NVS (Preferences).
- Подтвердить значения коэффициентов датчиков под конкретную схему.
- При необходимости добавить watchdog и heartbeat между контроллерами.


## Wi‑Fi и доступ к интерфейсу

В `esp32_controller.ino` добавлены оба режима:

- **STA**: подключение к вашему роутеру (`WIFI_SSID` / `WIFI_PASS`).
- **AP**: собственная точка доступа ESP32 (`AP_SSID` / `AP_PASS`).

Даже если роутер недоступен, интерфейс будет доступен через AP ESP32 по адресу `192.168.4.1`.

## Если Arduino IDE ругается на `#include <ESPAsyncWebServer.h>`

В этой версии проект переведён на стандартный `WebServer.h`, поэтому:

- ошибка с `ESPAsyncWebServer.h` исчезает;
- не требуется установка `ESPAsyncWebServer` и `AsyncTCP`.
