# Nasos: Arduino Nano + ESP32

## Архитектура

1. **`v1.ino` (Arduino Nano)**
   - читает аналоговые/дискретные входы;
   - управляет реле и VFD;
   - обменивается телеметрией и командами с ESP32.

2. **`esp32_controller.ino` (ESP32)**
   - логика двух насосов и защиты;
   - веб-интерфейс и API;
   - уставки в RAM (через меню настроек).

3. **`data/index.html`**
   - панель мониторинга;
   - раздел «Настройки» со всеми параметрами из кода;
   - кнопки сброса аварий и принудительного включения по каждому насосу.

## Подключение Nano ↔ ESP32

- `Nano D5 (TX SoftwareSerial)` → `ESP32 GPIO16 (RX2)`
- `Nano D4 (RX SoftwareSerial)` ← `ESP32 GPIO17 (TX2)`
- `GND Nano` ↔ `GND ESP32`

## API ESP32

- `GET /` — веб-интерфейс
- `GET /state` — текущее состояние
- `GET /settings` — текущие настройки
- `POST /set?param=...&value=...` — изменить параметр
- `POST /action?pump=well|house&cmd=...` — команды (`reset_alarm`, `force_on`, `force_off`)
- `GET /logs_well`, `GET /logs_house`
- `POST /clear_logs_well`, `POST /clear_logs_house`

## Wi‑Fi

ESP32 работает в режиме **AP + STA**:
- AP: подключение напрямую к плате (по умолчанию `Nasos-ESP32` / `12345678`)
- STA: подключение к роутеру (`wifi_ssid` / `wifi_pass` в настройках)

## Важное по принудительному режиму

- Для скважинного насоса принудительный режим обходит уровни бака.
- При этом защиты по току и таймерам остаются в приоритете.
- Аналогично для домашнего насоса: аварийные защиты всегда имеют приоритет.
