# Nasos: разделение на Arduino Nano + ESP32

## Что изменено

Проект разделён на два микроконтроллера:

1. **`v1.ino` (Arduino Nano)** — только I/O слой:
   - читает датчики тока, давления, уровней;
   - управляет реле скважинного насоса;
   - отправляет команды на VFD по RS-485 (Modbus);
   - обменивается телеметрией/командами с ESP32.

2. **`esp32_controller.ino` (ESP32)** — вся логика:
   - алгоритмы скважинного и домашнего насосов;
   - защиты по перегрузке и сухому ходу;
   - расчёт статистики (время работы, объём);
   - веб-сервер (LittleFS + WebSocket + REST API).

3. **`data/index.html`** — веб-дашборд для загрузки в LittleFS ESP32.

## Почему так лучше

- На Nano оставлены только «железные» задачи в реальном времени.
- Сложные вычисления, защита и UI перенесены на ESP32.
- Проще масштабировать: добавлять Wi‑Fi функции и аналитику без перегруза Nano.

## Рекомендуемое подключение Nano ↔ ESP32

Использован **UART** между ESP32 и Nano (просто и надёжно):

- `Nano D5 (TX SoftwareSerial)` → `ESP32 GPIO16 (RX2)`
- `Nano D4 (RX SoftwareSerial)` ← `ESP32 GPIO17 (TX2)`
- `GND Nano` ↔ `GND ESP32`

> На Nano аппаратный `Serial` остаётся для RS-485/VFD, поэтому для связи с ESP32 выбран `SoftwareSerial`.

## Протокол обмена

### Nano → ESP32 (телеметрия)
Строка раз в ~250 мс:

`TEL,<ms>,<well_I>,<well_P>,<house_I>,<house_P>,<L1>,<L2>,<L3>,<L4>,<vfd_run>,<vfd_freq>`

### ESP32 → Nano (команды)

`RELAY=<0|1>;VFD_RUN=<0|1>;VFD_FREQ=<Hz>`

## Веб-интерфейс ESP32

- Главная страница: `/`
- WebSocket поток: `/ws`
- Логи: `/logs_well`, `/logs_house`
- Настройки: `POST /set?param=SETPOINT_BAR&value=...`
- Экспорт CSV: `/export_well`, `/export_house`

## Библиотеки (ESP32)

- `ESPAsyncWebServer`
- `AsyncTCP`
- `LittleFS`
- `ArduinoJson`
