# Well pause backend + web UI update

## Что хранится в Preferences
- `pause_ms` (адаптивная/текущая длительность паузы) продолжает сохраняться в `well` namespace и восстанавливаться при старте.
- `wellPauseStart` **не сохраняется** и теперь дополнительно **явно** сбрасывается при старте ESP32 (`resetWellPauseTimer(...)` в `setup()`).

## Поведение таймера паузы после reboot
- После загрузки контроллера таймер паузы принудительно начинается с "нуля" uptime-базы:
  - `st.wellPauseStart = 0`.
- Это означает, что частично отработанная пауза с предыдущего аптайма не продолжается.
- Значение `pause_ms` при этом сохраняется как настроенное/адаптивное значение.

## Новые поля в `/state`
Добавлены поля:
- `pause_ms` — текущая длительность паузы (как и раньше).
- `pause_elapsed_ms` — сколько прошло с момента старта текущего countdown.
- `pause_remaining_ms` — сколько осталось до разрешённого старта (всегда `>= 0`, с clamp до 0).
- `pause_active` — `true`, если именно пауза в текущий момент блокирует автозапуск скважины.

Семантика `pause_remaining_ms`:
- если пауза не активна/не нужна — `0`;
- отрицательных значений нет;
- при ручном сбросе становится `0` сразу.

## Кнопка «Сброс паузы»
В веб-интерфейсе для скважины добавлена кнопка:
- `Сброс паузы` -> `POST /pump_action?pump=well&action=reset_pause`.

Действие кнопки:
- сбрасывает только countdown паузы (`wellPauseStart`),
- не сбрасывает аварии и блокировки,
- не снимает `pressureBlock`, `wellBlocked`, `wellAlarm`,
- не подменяет успешный запуск и не обходит защиты.

Логирование:
- при реальном активном countdown пишется: `Скважина: пауза сброшена вручную`.
- если активной паузы нет, лог не спамится.

## TFT/physical display
- TFT-интерфейс и физический дисплей намеренно **не изменялись**.
- Изменения внесены только в backend и web UI.
